1. App Overview

Sales Capture is a mobile iOS app that lets a business owner photograph a physical Z-report or sales receipt, automatically extract the cash and card payment totals using AI (Claude Vision), and instantly email a professional summary to a configured recipient.

Core Features

  • 📷 Camera Capture — take a photo of a Z-report or receipt directly in the app
  • 🖼️ Gallery Import — pick an existing photo from your iPhone's photo library
  • 🤖 AI OCR Extraction — Claude Vision reads the document and extracts cash & card totals
  • 📧 Email Summary — sends a professional HTML email via Resend API
  • ⚡ Auto-send — optional setting to send email automatically after every capture
  • 📋 History — view, review, and delete all past captured records
  • 🗑️ Delete Records — long-press or tap trash icon to delete any record
  • 💾 Persistent Storage — all data and receipt images saved on-device

TypeScript Data Types — types/index.ts

// One payment line item (e.g. "Visa" → $500.00)
interface PaymentEntry {
  description: string;  // payment method or label
  amount: number;       // dollar amount
}

// A complete captured sales record
interface SalesData {
  id: string;              // "sale_1716123456789" (timestamp-based)
  date: string;            // "2026-05-23" (YYYY-MM-DD)
  imageUri: string;        // local file path to receipt image
  cashPayments: PaymentEntry[];
  cardPayments: PaymentEntry[];
  cashTotal: number;
  cardTotal: number;
  confidence: 'high' | 'medium' | 'low';  // AI confidence score
  notes?: string;          // any notes from AI extraction
  emailSent: boolean;      // has email been sent for this record?
}

// App configuration stored in AsyncStorage
interface AppSettings {
  recipientEmail: string;  // where to send summaries
  senderName: string;      // "My Business" — appears in email from line
  autoSendEmail: boolean;  // auto-send after every capture?
  serverUrl: string;       // backend URL (Render or localhost)
}

Key Screens Explained

HomeScreen.tsx

The dashboard. Shows today's combined totals (cash + card + record count) in a summary card at the top. Below that, recent activity grouped by day. Tapping any record navigates to ReviewScreen.

CameraScreen.tsx

Live camera view using expo-camera. Has three modes:

  • Camera mode — live preview with flash toggle, flip camera, and gallery button
  • Preview mode — shows the captured photo with "Retake" and "Use Photo" buttons
  • Processing — shows a loading spinner while OCR runs on the backend

Gallery import uses expo-image-picker to open the iPhone photo library.

After OCR succeeds, navigates to Review with autoSend: true flag.

ReviewScreen.tsx

Shows the full extracted data: receipt thumbnail, confidence badge, cash payments list, card payments list, grand total. Has "Send Email Summary" button and "Retake Photo" button.

Auto-send logic: On mount, if the navigation param autoSend === true and the autoSendEmail setting is enabled, it automatically calls doSendEmail() without the user needing to tap anything.

HistoryScreen.tsx

All records grouped by date (Today, Yesterday, then actual dates). Each record shows a receipt thumbnail, time, confidence dot, cash/card breakdown, and total. Tap the 🗑️ button to delete. Long-press also triggers delete confirmation.

SettingsScreen.tsx

Four configurable fields:

  • Recipient Email — where summaries are sent
  • Sender Name — shown in the email "From" field
  • Auto-send Email — toggle: automatically email after each capture
  • Server URL — URL of the backend (Render URL or local IP for testing)

Claude Vision Service — claudeVision.ts

This is the core AI service. It sends the Base64 image to Anthropic's Claude model with a carefully crafted prompt:

// The prompt instructs Claude to:
// 1. Find all CASH payments and their amounts
// 2. Find all CARD/CREDIT payments and their amounts
// 3. Return ONLY a JSON object — no explanations
// 4. IMPORTANT: Do NOT count Credit Card Breakdown sub-sections
//    (those are already included in the card total above — counting
//    them would cause double-counting)
// 5. Mark confidence as high/medium/low based on readability

Claude returns a JSON string which the service parses and validates before returning to the app.

💡
Why this matters: Z-reports often have a "Credit Card Breakdown" section that lists each card type separately. Without the special instruction, Claude would add those amounts again on top of the already-counted card total, causing double the card total to appear.

Email Service — emailSender.ts

Builds a professional HTML email and sends it via the Resend HTTP API. The email includes:

  • Dark blue header with business name and date
  • KPI cards: Cash Total, Card Total, Grand Total, Record Count
  • Detailed table of cash payment items
  • Detailed table of card payment items
  • Grand total banner at the bottom
  • AI confidence indicator
  • Footer with "Sent via Sales Capture App"
// Resend API call
fetch('https://api.resend.com/emails', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${RESEND_API_KEY}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    from: 'Sales Capture <onboarding@resend.dev>',
    to: recipientEmail,
    subject: `Sales Summary — ${date}`,
    html: htmlTemplate
  })
})
⚠️ Why Resend instead of Gmail/SMTP?
Render.com's free tier blocks outbound SMTP ports (25, 465, 587). Resend uses HTTPS (port 443) which is always open, so emails send reliably from the server.

6. Complete Data Flow

Capture & OCR Flow

1
User takes photo or picks from gallery CameraScreen.tsx — uses expo-camera or expo-image-picker
2
Image is compressed and resized expo-image-manipulator resizes to max 1600px wide, 80% quality JPEG
3
Image encoded to Base64 expo-file-system reads the compressed file as a Base64 string
4
POST /api/extract sent to backend ocrService.ts sends {imageBase64, mimeType} to the Render server
5
Server calls Claude Vision API claudeVision.ts uses Anthropic SDK to send image + prompt to claude-3-5-sonnet
6
Claude reads the receipt and returns JSON AI extracts cash payments, card payments, totals, and confidence level
7
SalesData returned to app Server parses Claude's response and sends structured JSON back to the app
8
Image saved permanently on device ocrService.ts copies the photo to documentDirectory/receipts/ folder
9
Record saved to AsyncStorage storageService.ts saves the full SalesData object to device storage
10
Navigate to ReviewScreen App shows extracted data; if auto-send is on, email fires automatically

Email Send Flow

1
User taps "Send Email Summary" (or auto-send triggers) ReviewScreen calls emailService.sendSalesSummaryEmail(salesData)
2
App reads settings from AsyncStorage Gets recipientEmail and senderName from stored AppSettings
3
POST /api/email sent to backend Sends {salesData, recipientEmail, senderName} to the Render server
4
Server builds HTML email template emailSender.ts creates professional HTML with all payment details
5
Email sent via Resend API Resend delivers the email to the recipient's inbox
6
Record updated: emailSent = true storageService.updateSalesData marks the record as sent in AsyncStorage

Receipt Image Storage

When a receipt is captured, the photo is permanently stored at:

{FileSystem.documentDirectory}/receipts/{recordId}.jpg

This is inside the app's private documents folder on the iPhone. The image persists even if the app restarts. When a record is deleted, the image file is also deleted automatically.

💡
Why permanent storage? Temporary camera URIs get deleted when the camera session ends. Without copying to a permanent path, receipt thumbnails in History would show as broken images.

10. Email System

Email Provider: Resend

The app uses Resend (resend.com) instead of traditional SMTP because Render.com's free server tier blocks SMTP ports. Resend uses HTTPS, which always works.

  • Cash Payments Table — description + amount for each cash item
